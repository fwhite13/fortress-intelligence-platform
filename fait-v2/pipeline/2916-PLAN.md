# Task Brief: ADO#2916
## FAIT v2: Dashboard spinner hangs on S3/init exception — wire provisioning + graceful error state

**Risk Level:** Medium
**Pipeline Path:** Full (build → review → deploy)
**CSS-Variable Rule:** Applies to any new error UI elements

---

## Root Cause (from code investigation)

Two bugs combine to cause the infinite spinner:

1. **`/api/agent/status` is a stub** — `Program.cs` line 264: `app.MapGet("/api/agent/status", () => Results.Ok(new { status = "Starting" })).AllowAnonymous();` — always returns `"Starting"`, never `"Running"`. `AssistantLoadingState` polls this every 2s for up to 60s then shows a timeout state.

2. **`UserProvisioningService.ProvisionAsync` is never called** — The service exists and is registered but nothing triggers it. On first login, workspace S3 files and pgvector schema are never created. Any subsequent S3 call (WorkspaceService, MemoryFileService) throws `InvalidOperationException("AWS:WorkspaceBucket not configured")` or `AmazonS3Exception` (once bucket env var is wired via #2915).

---

## Acceptance Criteria

### 1. Wire `/api/agent/status` to actually trigger + report provisioning

Replace the stub with a real endpoint that:
- Reads the authenticated user's identity (Entra OID from claims)
- Calls `IUserProvisioningService.ProvisionAsync()` if the user is not yet provisioned
- Returns `{ "status": "Running" }` when provisioning is complete (or already was)
- Returns `{ "status": "Provisioning" }` while in progress (if async)
- Returns `{ "status": "Error", "message": "..." }` on exception

**Simplest correct implementation:** Make the endpoint synchronous-on-first-call — provision inline, return Running on success. The loading screen already handles up to 60s of polling; provisioning takes ~2-5s on first call.

```csharp
app.MapGet("/api/agent/status", async (
    HttpContext ctx,
    IUserProvisioningService provisioning,
    ILogger<Program> log,
    CancellationToken ct) =>
{
    var entraOid = ctx.User.FindFirst("http://schemas.microsoft.com/identity/claims/objectidentifier")?.Value
                ?? ctx.User.FindFirst("oid")?.Value;
    if (string.IsNullOrEmpty(entraOid))
        return Results.Ok(new { status = "Error", message = "Not authenticated" });

    var email = ctx.User.FindFirst("email")?.Value
             ?? ctx.User.FindFirst("preferred_username")?.Value
             ?? ctx.User.FindFirst("http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress")?.Value
             ?? "";
    var displayName = ctx.User.FindFirst("name")?.Value
                   ?? ctx.User.FindFirst("http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name")?.Value
                   ?? email;
    var userId = entraOid; // FAIT v2 uses entraOid as userId

    try
    {
        var result = await provisioning.ProvisionAsync(userId, entraOid, email, displayName, null, ct);
        return Results.Ok(new { status = "Running" });
    }
    catch (Exception ex)
    {
        log.LogError(ex, "Provisioning failed for user {UserId}", userId);
        return Results.Ok(new { status = "Error", message = "Initialization failed. Please refresh." });
    }
}).RequireAuthorization();
```

**Note:** Check `IUserProvisioningService.ProvisionAsync` signature — adapt the call accordingly. The method should already handle the "already provisioned" case gracefully (returns early if `OnboardingCompletedAt != null`).

### 2. Handle "Error" status in AssistantLoadingState

`AssistantLoadingState.razor` currently only checks for `"Running"` in the response. Add handling for `"Error"`:

```csharp
if (content.Contains("\"status\":\"Running\"") || content.Contains("\"status\":\"running\""))
{
    _pollTimer?.Dispose();
    await OnReady.InvokeAsync();
    return;
}
if (content.Contains("\"status\":\"Error\"") || content.Contains("\"status\":\"error\""))
{
    _pollTimer?.Dispose();
    _timedOut = true; // reuses the existing error/retry UI
    _statusMessage = "Initialization failed. Please refresh the page.";
    StateHasChanged();
    return;
}
```

Apply same fix to both the `OnInitialized` timer and the `Retry()` timer.

### 3. Graceful error display in AssistantLoadingState

The existing `_timedOut` state shows "Taking longer than expected." + a "Try again" button. For the Error case, update the message to something more useful. The `_statusMessage` set above ("Initialization failed. Please refresh the page.") will render in the existing `<p class="loading-status-message">` element. That's sufficient — no new UI needed.
