## Background

The FORGE KB MCP endpoint has moved to `https://mcp.fortressam.ai/mcp/forge-kb` with server-side environment awareness. All other tool groups (MS365, ADO, Web Search) must follow the same canonical pattern. 

**Current state in code:**
- `appsettings.json` has `FipMcp:EndpointUrl = https://api.fortressam.ai/mcp` (WRONG domain, wrong pattern)
- `Program.cs` seeds only `forge-kb` into `mcp_servers` with that single `FipMcp:EndpointUrl`
- `ForgeKbService.cs` calls `{FipMcp:EndpointUrl}/mcp` — producing `https://api.fortressam.ai/mcp/mcp` (double `/mcp`)
- MS365, ADO, and Web Search tool groups are NOT seeded into `mcp_servers` at all

**Target state:**
- `FipMcp:BaseUrl = https://mcp.fortressam.ai/mcp` (new key name, correct URL)
- All 4 tool groups seeded in `mcp_servers` with URLs: `https://mcp.fortressam.ai/mcp/{server}`
- `ForgeKbService` call URL simplified: `{BaseUrl}/forge-kb` (no double `/mcp`)

### 2. Fix ForgeKbService URL construction

### 3. Seed all 4 tool groups in Program.cs
Replace the single `forge-kb` seed block with an idempotent seed for all 4 tool groups. Use a single loop pattern:

```csharp
var baseUrl = cfg["FipMcp:BaseUrl"]?.TrimEnd('/') ?? "https://mcp.fortressam.ai/mcp";

var toolGroups = new[]
{
    new { Name = "forge-kb",   AuthType = "none",        DefaultRead = true,  DefaultWrite = false },
    new { Name = "ms365",      AuthType = "oauth_entra", DefaultRead = true,  DefaultWrite = false },
    new { Name = "ado",        AuthType = "oauth_entra", DefaultRead = true,  DefaultWrite = false },
    new { Name = "web-search", AuthType = "none",        DefaultRead = true,  DefaultWrite = false },
};

foreach (var tg in toolGroups)
{
    var expectedUrl = $"{baseUrl}/{tg.Name}";
    var existing = await seedDb.McpServers.FirstOrDefaultAsync(s => s.Name == tg.Name);
    if (existing == null)
    {
        seedDb.McpServers.Add(new McpServer
        {
            Id = Guid.NewGuid().ToString(),
            Name = tg.Name,
            EndpointUrl = expectedUrl,
            AuthType = tg.AuthType,
            DefaultRead = tg.DefaultRead,
            DefaultWrite = tg.DefaultWrite,
            IsActive = true,
            CreatedAt = DateTime.UtcNow
        });
        seedLogger.LogInformation("Seeded mcp_servers entry: {Name}", tg.Name);
    }
    else
    {
        bool changed = false;
        if (existing.EndpointUrl != expectedUrl) { existing.EndpointUrl = expectedUrl; changed = true; }
        if (existing.AuthType != tg.AuthType) { existing.AuthType = tg.AuthType; changed = true; }
        if (changed)
        {
            seedLogger.LogInformation("Updated mcp_servers entry: {Name}", tg.Name);
        }
    }
}
await seedDb.SaveChangesAsync();
```

### 4. No database migration needed
`mcp_servers` schema is unchanged. New rows are inserted at startup via the seeder above — no EF migration required. ✅

## Key Architecture Note (from spec §7.0)
> FAIT v2 does not embed MCP adapters inside the application container. All MCP tool groups are external services hosted on `fip-mcp`, accessed over HTTPS.

The FAIT v2 app is a *caller* — it doesn't run MS365/ADO/search logic itself. The `mcp_servers` table records the external endpoints. `ConnectorService` reads those for display. Only `ForgeKbService` makes actual HTTP calls to fip-mcp today (the rest are wired for future Sprint 3 integration).
