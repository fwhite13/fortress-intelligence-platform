### Important Issues — 1

#### I1: `ApplyTableKeepTogether` — InsertAt duplicate when row already has TableRowProperties

- **File:** `WordDocumentGenerator.cs` — `ApplyTableKeepTogether` method
- **Category:** Correctness (latent)
- **Issue:** When a TableRow already has a `TableRowProperties` child, `GetFirstChild<TableRowProperties>()` returns the existing node. The code then appends `CantSplit` to it and calls `row.InsertAt(trPr, 0)`. In the OpenXml SDK, `InsertAt` with an element already present in that parent **inserts a second copy at position 0**, leaving the original in place. The result is two `<w:trPr>` elements in the same row — malformed OOXML.
- **Runtime impact in this WI:** Zero. No tables are generated by this WI's code paths. `ApplyTableKeepTogether` is unreachable from `GenerateAsync` as implemented.
- **Impact when tables are added:** First call to `ApplyTableKeepTogether` on any row that already has `TableRowProperties` produces a broken table row. Word silently tolerates duplicates but OOXML validators will flag it.
- **Fix:**
  ```diff
  - var trPr = row.GetFirstChild<TableRowProperties>() ?? new TableRowProperties();
  + var existingTrPr = row.GetFirstChild<TableRowProperties>();
  + var trPr = existingTrPr ?? new TableRowProperties();
    trPr.AppendChild(new CantSplit());
    // ... conditional KeepNext/KeepLines ...
  - if (trPr.HasChildren)
  -     row.InsertAt(trPr, 0);
  + if (existingTrPr == null && trPr.HasChildren)
  +     row.InsertAt(trPr, 0);
  ```

### Nitpick Issues — 3

#### N1: `AddPageNumberFooter` — orphaned SectionProperties on null-path

- **File:** `WordDocumentGenerator.cs` — `AddPageNumberFooter`
- **Code:**
  ```csharp
  var sectPr = mainPart.Document.Body!.GetFirstChild<SectionProperties>()
      ?? new SectionProperties();
  sectPr.AppendChild(footerRef);
  ```
- **Issue:** If `GetFirstChild<SectionProperties>()` returns null, a new SectionProperties is created, footerRef is appended to it, but this object is **never added to the body**. The footer relationship exists in the package but the document body doesn't reference it — footer silently disappears.
- **Actual risk:** Near-zero in practice. `body.AppendChild(new SectionProperties())` is called at line 46, then `mainPart.Document = new Document(body)` at line 48 — SectionProperties is always present. The null path is unreachable under normal execution.
- **Recommended fix:** Add an assertion or throw-on-null to make the invariant explicit:
  ```csharp
  var sectPr = mainPart.Document.Body!.GetFirstChild<SectionProperties>()
      ?? throw new InvalidOperationException("SectionProperties not found in document body.");
  sectPr.AppendChild(footerRef);
  ```

#### N2: `ApplyTableKeepTogether` comment claims `w:tblHeader` behavior that isn't implemented

- **File:** `WordDocumentGenerator.cs` — XML doc comment on `ApplyTableKeepTogether`
- **Issue:** Comment says `"Header rows get w:tblHeader"` but no code in the method sets `tblHeader` on any row. The method only applies `CantSplit`, `KeepNext`, and `KeepLines`.
- **Fix:** Remove the inaccurate bullet from the doc comment, or implement `w:tblHeader` on the first row when tables are actually added.

#### N3: `content.Split('\n')` — Windows line endings

- **File:** `WordDocumentGenerator.cs` — `ParseSectionContent`
- **Issue:** `content.Split('\n')` does not handle `\r\n` (Windows CRLF). Lines from Windows-origin content will include a trailing `\r` in the text, which renders as a literal carriage-return character in the Word paragraph.
- **Fix:**
  ```diff
  - foreach (var line in content.Split('\n'))
  + foreach (var line in content.Split(new[] { "\r\n", "\n" }, StringSplitOptions.None))
  ```
