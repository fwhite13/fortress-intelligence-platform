## Changes Made

### `fait-v2/agent-harness/harness-server.js`

**ADO#3278 — Suppress empty `kb_sources` SSE event**
- Location: `~line 1921`, Bedrock ConverseStream path, inside `if (kbEnabled)` block
- Removed the `else` branch that emitted `event: kb_sources` with `{ sources: [], wasSearched: true }` when KB was searched but returned 0 results
- Previously: Blazor received this empty event, set `KbRetrievalResult.WasSearched = true`, and `KbIndicator` rendered "📚 KB searched — no relevant results" on every message
- Now: silence when no KB results — `KbIndicator` only appears when there are actual KB matches

**ADO#3280 — Sanitize `generate-document` error handler**
- Location: `app.post('/tools/create_document', ...)`, `if (!genRes.ok)` block (~line 914)
- HTML detection: `errText.trim().startsWith('<') || errText.includes('<!DOCTYPE')`
- When HTML: returns clean `"Document generation failed (HTTP {status}). The API returned an unexpected response."`
- When non-HTML: returns truncated (first 200 chars) raw error text

**ADO#3280 — Sanitize `read_memory` error handler**
- Location: `app.post('/tools/read_memory', ...)`, `if (!resp.ok)` block (~line 845)
- Same HTML detection pattern
- When HTML: `[non-JSON response, HTTP {status}]`
- When non-HTML: `text.substring(0, 200)`

### `fait/src/FortressAI.Web/Components/Chat/ChatView.razor`

**ADO#3277 — Resumption brief double-fire guard**
- Location: `HandleAgentReady()` method, immediately after `_ = CheckFailedTasksAsync();`
- Added: `if (_resumptionBriefSent) { Logger.LogDebug(...); return; }`
- Prevents `_wasColdStart = true` from being set when brief already sent this render cycle
- Guards against race: `HandleAgentReady` called twice (once by `AssistantLoadingState` polling, once by warm-path lifecycle) would previously both set `_wasColdStart = true`, potentially triggering a second brief before the storage guard had written back

### `fait/src/FortressAI.Web/Components/Pages/Tasks.razor`

**ADO#3279 — RunNow missing `EnabledMcpSlugs`**
- Added `@inject IMcpToolService McpToolSvc`
- In `RunNowAsync()`, before `TurnRequest` construction: resolves active MCP server slugs via `McpToolSvc.GetActiveServersForUserAsync(userId)`
- Passes `EnabledMcpSlugs: resolvedMcpSlugs` to `TurnRequest`
- Resolution is best-effort (try/catch, continues with `null` on failure)
- Mirrors the existing logic in `ScheduledTaskBackgroundService.ProcessTaskAsync`

## Known Edge Cases / Notes for Clint

1. **#3278**: The `kbEnabled` check + `if (kbSources.length > 0)` now means no `kb_sources` event fires at all when KB is searched but empty. The `KbRetrievalResult` field `_lastKbResult` stays `null`, so `KbIndicator` renders nothing. This is intentional per the bug spec.

2. **#3279**: `McpToolSvc.GetActiveServersForUserAsync` is a DB call on the hot path of `RunNow`. It's inside `Task.Run` (background thread) so it doesn't block the UI. If it fails, task runs without MCP tools (graceful degradation, same as before the fix).

3. **#3277**: The guard only prevents `_wasColdStart` from being set when `_resumptionBriefSent` is already `true`. The brief will still fire once on a true cold start where the agent transitions warm.

4. **#3280**: The HTML detection uses two checks (`startsWith('<')` after trimming, and `includes('<!DOCTYPE')`). This covers Cloudflare challenge pages, 502 error HTML, and ALB 503 responses.
